# SwipeCaptchaDriver.php
<!-- DOCGEN:END -->

`ST_system\Captcha\Drivers\SwipeCaptchaDriver` — ручку на дорожке нужно перетащить слева
направо. Работает и мышью, и пальцем: используются Pointer Events, без mouse-специфики.

Имя драйвера — `swipe`.

## Конфигурация

| Ключ | По умолчанию | Назначение |
|------|--------------|------------|
| `target` | `100` | до какого процента дорожки нужно дотащить ручку, 10..100 |
| `tolerance` | `4` | допустимое отклонение в процентах, 1..50 |

Плюс общие ключи `CaptchaDriver`. По умолчанию цель — конец дорожки; промежуточное значение
имеет смысл задавать, только если приложение само рисует метку, куда тащить.

## Проверка

JS пишет в поле ответа JSON `{"pct": <процент>, "path": [[мс, смещение], ...]}`.

Сервер проверяет две вещи:

1. Конечная позиция попадает в `target ± tolerance`.
2. Траектория монотонна: доля движений назад (более чем на 2 пикселя) не превышает 25 % точек,
   и точек не меньше четырёх. Мгновенный «телепорт» ручки в конец дорожки проверку не проходит.

Дополнительно `forcedSignals()` принудительно включает группу `basic` поведенческого слоя.
`pointerdown` игнорируется при `event.isTrusted === false`, поэтому синтетический драг
автоматизации не запускает перетаскивание вовсе.

Если ручку отпустили далеко от цели (более 20 % отклонения), виджет возвращает её в начало,
сбрасывает записанную траекторию и переходит в состояние `invalid` — можно пробовать снова.

```php
$captcha = CaptchaManager::swipe('contacts', ['tolerance' => 2]);

Assets::addString($captcha->includeCss(), 'head');
Assets::addString($captcha->includeJs(),  'footer');
echo '<form method="post">'.$captcha->putCaptcha().'<button>Send</button></form>';
```

CSS минимальный: `.st-captcha-track` — 260×36 с рамкой и `touch-action: none`,
`.st-captcha-handle` — 36×36. Оформление добавляет приложение.

См. также: `Captcha\Behavior`, `Captcha\CaptchaDriver`.
