# Simulation.php
<!-- DOCGEN:END -->

`ST_system\Captcha\Drivers\Game\Simulation` - серверная копия игры для
[GameCaptchaDriver](GameCaptchaDriver.php.md). Зеркало `assets/engine/src/sim.js`: каждая игра
пишется дважды, и обе версии обязаны совпадать до бита.

## Жизненный цикл

`idle` (ждёт первого ввода) → игра → `lose()` → `dead` тиков паузы (`cooldown()`) → `restart()` →
снова `idle`. `setup()` вызывается один раз на партию - для того, что переживает смерть (лабиринт,
карта). `score()` прибавляет реакцию и поднимает `peak` - лучший счёт.

Из `idle` выводит любой ввод. Код `Simulation::START` (15) - кнопка старта или перезапуска на поле:
он выводит из `idle`, но в `handle()` не уходит и действием не считается. Смерть капчу не
проваливает: после паузы игрок перезапускает игру, `tick`, `acts`, `good` и `peak` копятся дальше.

`params['per_life']` (по умолчанию `true`): `lose()` обнуляет `reactions`, и `peak` - лучший счёт за
одну жизнь. При `false` счёт копится через смерти.

## Осмысленные действия

`intent($good)` отмечает действие, по которому видно намерение: `acts` растёт всегда, `good` - если
действие было ответом на ситуацию. Что считается таким действием, решает игра (см. её страницу).
Оба счётчика входят в `state()` и `digest()`, и по ним драйвер решает, засчитывать ли цель
(`goal_ratio`) и как оценить игру без цели (`GameCaptchaDriver::gameScore()`).

## replay()

```php
$sim = SnakeSimulation::replay($seed, $params, $log, $ticks);
```

На тике N сначала применяются все вводы с меткой N, затем шаг; всего `$ticks` шагов. С `$goal > 0`
прогон останавливается, как только `peak` достиг цели (до шага или после). Драйвер так не делает:
клиент засчитывает цель только вместе с долей осмысленных действий и может играть дальше, поэтому
итог считается на присланном тике. Лог должен быть уже проверен `GameCaptchaDriver::normalizeLog()`.

`state()` - состояние целыми числами, `digest()` - его crc32. По `digest` тесты сверяют PHP-копию
с JS на одном и том же логе.
