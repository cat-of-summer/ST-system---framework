# GameCaptchaDriver.php
<!-- DOCGEN:END -->

`ST_system\Captcha\Drivers\Game\GameCaptchaDriver` - основа капч-мини-игр. Пройти игру не нужно:
партия длится не дольше 20 секунд, за это время игрок набирает `goal` реакций - съесть яблоко,
пролететь трубу, отбить мяч - или просто играет осмысленно, и капча засчитывается по запасному
пути. Цель игроку не показывается: в строке счёта только счёт, а решает сервер.

| Драйвер | Игра | Реакция | `goal` | Тиков/с |
|---------|------|---------|--------|---------|
| `snake` | [Змейка](Snake/SnakeCaptchaDriver.php.md) без стен | съедено яблоко | 2 | 24 |
| `flappy` | [Flappy Bird](Flappy/FlappyCaptchaDriver.php.md) | пройдена труба | 3 | 30 |
| `arkanoid` | [Арканоид](Arkanoid/ArkanoidCaptchaDriver.php.md) | мяч отбит ракеткой | 2 | 30 |
| `tetris` | [Тетрис](Tetris/TetrisCaptchaDriver.php.md) 8×14 | убрана линия | 1 | 20 |
| `pacman` | [Пакман](PacMan/PacManCaptchaDriver.php.md) | съедена вишня | 2 | 10 |
| `battlecity` | [Battle City](BattleCity/BattleCityCaptchaDriver.php.md) | подбит враг | 2 | 20 |
| `puzzle` | [Пазл](Puzzle/PuzzleCaptchaDriver.php.md) из ваших картинок | кусочек на своём месте | все | 10 |

Поле каждой игры подстраивается под размер холста `size`: сетка змейки, лабиринт пакмана и поле
танков получают столько клеток, сколько помещается; мир Flappy Bird и арканоида - ширину под
пропорции; тетрис и пазл подбирают размер клетки. Как именно - на странице игры.

```php
$captcha = CaptchaManager::snake('contacts', ['goal' => 3, 'size' => [400, 240]]);

Assets::addString($captcha->includeCss(), 'head');
Assets::addString($captcha->includeJs(),  'footer');
echo '<form method="post">'.$captcha->putCaptcha().'<button>Send</button></form>';

// обработчик формы
$captcha = CaptchaManager::snake('contacts');
if (!$captcha->check($_POST)) { /* отказ: $captcha->error */ }
$captcha->via;   // 'goal' | 'fallback' — каким путём пройдено
```

## Как проверяется

Клиенту не верят. Сервер выдаёт `seed`, браузер играет детерминированной игрой и присылает только
**лог вводов** - `{"t": <тиков сыграно>, "log": [[тик, код, значение?], ...]}`. `verify()` прогоняет этот
лог своей копией игры на PHP ([Simulation](Simulation.php.md)) до тика `t` и смотрит на итог.

Обе копии считают не только реакции, но и **осмысленные действия**: из всех действий, по которым
видно намерение (`acts`), сколько были ответом на ситуацию (`good`). Что это значит в каждой игре -
на её странице: поворот к яблоку, взмах под зазором, ракетка к падающему мячу и так далее.

Зачёт - по одному из двух путей:

1. **Цель** (`via = goal`): `peak ≥ goal` (лучший счёт за жизнь или за партию, см. `per_life`) и
   `good ≥ goal_ratio · acts`. Набранное вслепую не засчитывается: у случайных нажатий осмысленных
   действий около половины, у игрока - почти все.
2. **Запасной путь** (`via = fallback`): сыграно не меньше `fallback.time` секунд, действий с
   намерением не меньше `fallback.actions`, и среди них осмысленных не меньше `fallback.ratio`.
   Поверх этого нужен поведенческий скоринг не ниже `fallback.score` вместо обычного `min_score`
   (хук `CaptchaDriver::requiredScore()`), иначе `error === 'behavior'`.

**Что делает браузер.** Цель и пороги качества в браузер не уходят - их знает только серверная
копия. Браузер ставит галочку и отдаёт лог форме, когда:
- данных достаточно (`collect` в публичном конфиге): сыграно не меньше `fallback.time` секунд и
  действий с намерением не меньше `fallback.actions`, - хорошо ли сыграно, не важно;
- или вышло `max_time` (по умолчанию 20 секунд): отдаётся то, что набрано.

Засчитывать или нет, решает сервер. Если запасной путь выключен, `collect` пуст и браузер отдаёт
лог по истечении `max_time`.

**Проигрыш в игре - не провал капчи.** После смерти пауза около секунды и кнопка перезапуска;
время партии идёт, действия и лучший счёт копятся дальше.

Пороги подобраны ботами: генератор фикстур гоняет бота и случайные нажатия разного темпа на сотнях
seed. Бот проходит в 91-100 % партий не дольше чем за 12 секунд, случайные нажатия - не чаще чем в
2 % (их дальше отсекает поведенческий скоринг запасного пути).

Перед прогоном лог отсеивается без исключений, отказ - `error === 'answer'`:

- `t` и все поля событий - целые числа; событие - 2 или 3 элемента;
- тики не убывают и не больше `t`; код 0..15 (15 - `START`: кнопка старта или перезапуска, в игру
  не уходит и действием не считается), значение по модулю не больше 100 000;
- не больше 8 событий на тик и `max_events` всего;
- `t` не больше `max_time` секунд игры;
- **по часам**: `t / tps` не больше `time() - issued_at + clock_slack`. Партию нельзя прислать
  быстрее, чем её можно сыграть.

`forcedSignals()` включает группу `basic` поведенческого слоя, повтор решения закрыт общей
защитой от replay (`error === 'replayed'`).

> [!warning]
> Игровые капчи недоступны незрячим и людям, которые не могут быстро управлять клавиатурой или
> пальцем. Дайте альтернативу - `text` или `checkbox`.

## Конфигурация

| Ключ | По умолчанию | Назначение |
|------|--------------|------------|
| `goal` | по игре | сколько реакций набрать, 1..50; браузеру не отдаётся |
| `goal_ratio` | `0.6` (у арканоида `0.75`) | доля осмысленных действий, без которой цель не засчитывается, 0..1 |
| `per_life` | `true` | цель за одну жизнь; `false` - счёт копится через смерти |
| `fallback` | `['time' => 8, 'actions' => 10, 'ratio' => 0.6, 'score' => 0.7]` | запасной путь и порог сбора данных; `false` - выключить. Частичный массив дополняется значениями игры (у каждой игры свои `actions` и `ratio` - см. её страницу) |
| `big_button` | `left` | сторона большой кнопки геймпада на телефоне: `left` или `right`; крестовина - на другой стороне |
| `hint` | по игре, на русском | подсказка по управлению на стартовом экране: `['keys' => '…', 'touch' => '…']` - с клавиатуры и на телефоне. Частичный массив дополняется подсказкой игры; так подсказку переводят на другой язык |
| `size` | `[320, 200]` | холст `[ширина, высота]` в CSS-пикселях, 200..960 × 140..960; из них 20 px сверху - строка счёта. Задаёт и пропорции, и размер поля игры (см. выше) |
| `max_time` | `20` (у пазла `60`) | сколько секунд длится партия, 10..600; дальше браузер отдаёт то, что набрано |
| `max_events` | `4000` | максимум событий в логе, 50..20000 |
| `clock_slack` | `2` | запас в секундах для проверки по часам |

Плюс общие ключи `CaptchaDriver`. Ключи игры задаются как у остальных драйверов:
`CaptchaManager::setConfig(['drivers.tetris.goal' => 2, 'drivers.snake.fallback' => false])` или в
конфиге экземпляра. `putCaptcha(['seed' => N])` фиксирует seed - для тестов и демо; по умолчанию он
случайный.

## Клиент

- Canvas в **закрытом** shadow root внутри `.st-captcha-game`: CSS страницы виджет не ломает,
  состояние игры не попадает в DOM, а партия живёт в замыкании, а не на объекте из
  `STCaptcha.instances`.
- Размер: виджет занимает `size[0]` CSS-пикселей в ширину (не шире контейнера) с пропорциями
  `size`, буфер canvas - CSS-размер × `devicePixelRatio`. Раскладку поля под `size` считает
  сервер (`layout()`) и отдаёт обеим копиям игры в `params`, так что браузер и PHP играют на одном
  поле. На телефоне холст вписывается в экран целиком, с сохранением пропорций.
- Симуляция идёт фиксированными тиками, отрисовка - по `requestAnimationFrame` отдельно от них.
  Игра ставится на паузу, когда виджет вне экрана.
- **Строка счёта** - значок игры и счёт (у арканоида - разбитые кирпичи). Цели и полоски прогресса
  нет.
- **Кнопки на поле** - круг со знаком, в одном стиле:
  - треугольник - старт, под ним подсказка по управлению (`hint`) текстом;
  - скруглённая стрелка - перезапуск после смерти;
  - галочка - данные собраны или время вышло, ответ отдан форме.

  Клик или тап по полю, пока показан старт или перезапуск, нажимает кнопку (в лог уходит код
  `START`). Игровые клавиши, пробел и Enter тоже запускают.
- **Ввод трёх видов**, все - в движке:
  1. **Геймпад** - конструктор из крестовины (четыре стрелки или пара ◀ ▶) и одной большой
     кнопки. Игра объявляет, какие кнопки ей нужны, и получает их нажатия и отпускания.
  2. **Клавиатура наследует геймпад**: стрелки и WASD (и кириллица на тех же местах) - крестовина,
     пробел и Enter - большая кнопка. Игра может добавить или убрать клавиши в своём JS-проекте
     (`keys`); клавиши вне раскладки уходят игре как есть (так управляется пазл).
  3. **Жесты по полю** (мышь и палец) - только у игр, которые их включили (`pointer`); из
     встроенных это пазл. В остальных клик и тап по полю только дают фокус и нажимают кнопку старта
     или перезапуска; тапы и свайпы в игру не уходят.

  Потеря фокуса и смерть отпускают зажатые кнопки и клавиши.
- **Телефон** (`pointer: coarse`): виджет - кнопка запуска с подсказкой для пальца. Тап
  разворачивает игру поверх страницы (`position: fixed`, отдельный закрытый shadow root на
  `body`, отступы под вырезы экрана; Fullscreen API не нужен, на iOS его нет). Поле вписывается в
  экран по пропорциям, геймпад - в портрете под полем, в альбоме по бокам от него.
  - Большая кнопка во всех играх выглядит одинаково (круг 108 px с точкой); её сторона -
    `big_button`, крестовина - на другой.
  - **Кнопки мягкие, как в мобильных играх**: увёл палец с кнопки - она отпустилась, довёл до
    соседней - нажалась та. Палец можно поставить и мимо кнопки. Пальцы независимы: крестовина и
    большая кнопка жмутся одновременно.
  - Автоповтор - у кнопок, которые игра для этого отметила (сдвиг в тетрисе).
  - Прокрутка страницы на это время заблокирована; ✕ закрывает игру (партия на паузе), после
    галочки она закрывается сама.
- Режим ввода отслеживается: подключили мышь или включили касания - меняются подсказка и способ
  запуска.
- События с `isTrusted === false` игнорируются.

## Устройство и сборка

```
src/Captcha/Drivers/Game/
  GameCaptchaDriver.php  Simulation.php  Rng.php
  <Игра>/
    <Игра>CaptchaDriver.php  <Игра>Simulation.php
    package.json  src/sim.js  src/index.js  [src/controls.js]  test/bot.js
    dist/game.min.js     собранный бандл; его встраивает driverJs()
  assets/
    package.json         корень npm: workspaces engine и ../<Игра>, esbuild
    engine/src/          общий клиентский движок: Sim, Rng, обвязка, геймпад
    test/                JS-тесты (*.test.js) и генератор фикстур (fixtures.js)
```

Игры импортируют движок относительным путём (`../../assets/engine/src/…`): `node_modules` лежат в
`assets/`, а не выше папок игр.

`dist/` хранится в git рядом с исходниками, в composer-пакет уходят только PHP и `dist`, исходники
JS исключены в `.gitattributes`. Node в рантайме не нужен: PHP только читает готовый бандл.

> [!warning]
> После правки JS пересоберите бандлы и фикстуры и закоммитьте их вместе с исходниками. CI
> собирает `dist` и фикстуры заново и падает, если они расходятся с закоммиченными. Без `dist`
> игровые драйверы недоступны (`isAvailable() === false`, `CaptchaManager` бросает
> `RuntimeException`).

```bash
cd src/Captcha/Drivers/Game/assets
npm ci
npm run build   # esbuild → <Игра>/dist/game.min.js
npm test        # JS-тесты + фикстуры tests/Fixtures/Captcha/Game/<игра>.json
```

`npm test` - это `node --test` (движок, правила каждой игры, счётчики осмысленных действий,
перезапуск после смерти, управление ракеткой и танком) и генератор фикстур. Генератор падает, если
бот не дотягивает до цели или, играя как браузер, до запасного пути за `max_time`, или если
случайные нажатия (редкие и частые) проходят хоть одним путём.

После правки игры пересобрать бандл и фикстуры и прогнать PHPUnit (`tests/Unit/Captcha/Game`):
тест сверяет итоговое состояние PHP-копии с JS по `digest` (включая `acts`/`good`), значения по
умолчанию - с `assets/test/games.js`, и требует собранный `dist`.

### Детерминизм

`sim.js` и `<Игра>Simulation.php` - одна игра на двух языках, и совпадать они обязаны до бита:

- только целые числа; физика в фиксированной точке ×256; пороги долей - целые проценты;
- деление - `idiv` (JS) и `intdiv` (PHP), оба с усечением к нулю;
- случайность только из [Rng](Rng.php.md) (xorshift32); порядок вызовов `rng` одинаковый,
  включая короткие замыкания - вызов `rng` ставится первым операндом;
- наследник `Sim` в JS не объявляет полей класса: инициализаторы полей сработали бы после
  конструктора и затёрли бы состояние, заполненное `setup()` и `restart()`.

### Новая игра

1. Папка `<Игра>/` с `package.json` по образцу соседних; путь `../<Игра>` в workspaces
   `assets/package.json`.
2. `src/sim.js` - наследник `Sim`: `setup()`, `restart()`, `start()`, `handle(code, value)`,
   `update()`, `dump()`, при нужде `cooldown`. Реакция - `this.score()`, смерть - `this.lose()`,
   осмысленное действие - `this.intent(good)`.
3. `<Игра>Simulation.php` - то же на PHP.
4. `src/index.js` - `createDriver({name, Sim, render, icon, pad, controls})`:
   - `pad: {dpad: ['up', 'right', 'down', 'left'] | ['left', 'right'], big: true, repeat: [...]}` -
     нужные кнопки;
   - `controls(api).button(name, down, repeat)` получает `up | right | down | left | big` и
     возвращает `true`, если кнопка взята;
   - при нужде `score(sim)` - число в строке счёта.

   Размер холста приходит в `view.W`/`view.H` и `api.W`/`api.H`; клетку под него даёт
   `fitGrid(cols, rows, W, H)`.
5. `<Игра>CaptchaDriver.php` - `simulation()`, `tps()`, `defaultGoal()`, `defaultHint()`, при
   нужде `defaultFallback()`, `defaultGoalRatio()`, `defaultMaxTime()` и
   `layout(int $w, int $h)` - параметры поля под холст (константа `HUD` - высота строки счёта,
   `clamp()` - округлить и зажать); регистрация в `CaptchaManager` `drivers.available`.
6. `test/bot.js`, строка в `assets/test/games.js` (с `layout` для холста 320×200), тесты правил в
   `assets/test/games.test.js`;
   `npm run build && npm test`, PHPUnit.

### Что ещё умеют драйвер и движок

Нужно не каждой игре; пазл пользуется всем.

**PHP - `prepare(array $params, int $seed): array`.** Дополнения выдачи:
- `params` - обеим копиям игры;
- `secret` - только серверной копии, браузер их не получает. Так пазл держит в секрете
  перестановку кусочков;
- `public` - в публичный конфиг: спрайт, узор и прочее, что нужно для отрисовки;
- `goal` - цель этой выдачи вместо настроенной (тоже только серверной копии).

**JS - флаги `createDriver()`:**

| Ключ | Что делает |
|------|-----------|
| `keys: {клавиша: кнопка \| null}` | свои клавиши поверх унаследованных от геймпада: Flappy Bird добавляет стрелку вверх к большой кнопке, `null` убирает клавишу |
| `pointer: true` | жесты по полю мышью и пальцем: `controls().press(x, y)`, `move(x, y)`, `up(x, y, ok)` |
| `controls().key(key, down, repeat)` | клавиши, которых нет в раскладке геймпада (своя клавиатура пазла) |
| `open: true` + `ready(sim)` | открытый финиш: клиент не знает, решено ли, - когда `ready`, ответ отдаётся форме, но игра не замирает; стало не готово - ответ снят |
| `score(sim)` | число в строке счёта вместо `sim.reactions` |
| `progress(sim)` → `[сколько, из скольких]` | своя шкала в строке счёта, например занятые ячейки пазла |
| `startScreen: false` | без кнопки старта: игра начинается с первого хода |
| `controls().up(x, y, ok)` | отпускание пальца или кнопки мыши с координатами (`ok = false` - отмена) |
| `controls().render(ctx, sim, view)` | отрисовка из состояния управления (раскладка, перетаскивание); `api.cfg` - публичный конфиг выдачи |

См. также: `Captcha\CaptchaDriver`, `Captcha\Behavior`, [Simulation](Simulation.php.md).
